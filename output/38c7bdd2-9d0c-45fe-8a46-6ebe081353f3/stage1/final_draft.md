## 1. 摘要

小宝工作台是一款面向个人用户的「全记录 + 轻回顾」效率工具，以微信小程序与单文件 Web 应用（PWA）双端形态交付。产品将计划、课程、运动、备考、理财、自媒体、阅读、技能、便签、复盘等 15 类日常记录收敛到同一个入口，并通过日历热力图、日历时间轴、自动成长报告与全局搜索，把「记下来」变成「看得见」，最终形成可持续的自我管理闭环。

本文为产品的权威需求说明，包含 5 项产品目标、33 条功能需求（FR-001 至 FR-014、FR-101 至 FR-116、FR-201 至 FR-203）、7 类非功能要求、交互与视觉规范、数据模型、技术架构约束、里程碑状态、验收标准与风险清单。

**当前状态**：核心记录层、组织层、回顾层、激励层、智能层、数据层均已交付；提醒层本地能力已交付、微信订阅消息后台推送待配置；小程序与 Web 双端数据互通列为 M5 规划项。

## 2. 背景与问题陈述

### 2.1 现状

个人日常管理的数据天然是分散的：计划写在便签里，花销记在记账应用中，读书进度靠记忆，备考与课程进度靠心算，运动打卡靠自觉。市面上并不缺少单点优秀的工具，但缺少一个「今天所有事都在一处」的容器。

### 2.2 三个具体问题

| 编号 | 问题 | 表现 | 后果 |
| --- | --- | --- | --- |
| P1 | 记录入口分散 | 想记一件事之前，先要判断「该打开哪个应用」 | 记录成本高，最终演变为「干脆不记」 |
| P2 | 缺少反馈闭环 | 记完之后没有任何可视化回馈 | 无法形成习惯，用户质疑「记了又怎样」 |
| P3 | 回顾成本过高 | 想知道上周做了什么，需要翻多个地方 | 周复盘几乎不可能坚持 |

### 2.3 机会

若能把记录入口收敛为一处、把记录结果即时可视化、把回顾动作压缩为一次点击，则个人管理工具的使用频次与留存均有显著改善空间。这正是本产品切入的位置。

## 3. 目标与非目标

### 3.1 产品目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 一个入口完成全天 15 类记录 | 15 个模块全部可用；单模块完成一次记录不超过 3 次点击 |
| G2 | 降低单次记录成本 | 提供模板库、快速添加入口、表单默认值与快捷按钮 |
| G3 | 建立正反馈闭环 | 打卡连续天数、日历热力图、自动成长报告、战绩卡片 |
| G4 | 让回顾变得简单 | 日历时间轴（任意一天全记录）、全局搜索、周复盘自动汇总 |
| G5 | 数据自主可控 | 本地优先存储；支持一键导出与恢复备份 |

### 3.2 成功指标（建议追踪）

| 指标 | 定义 | 目标值 |
| --- | --- | --- |
| 日均记录条数 | 每日新增记录总条数 / 活跃天数 | 不低于 5 条 |
| 模块覆盖度 | 周内有记录的模块数 / 15 | 不低于 6 个 |
| 打卡连续性 | 月度最长连续打卡天数 | 不低于 21 天 |
| 周复盘完成率 | 已提交周复盘的周数 / 总周数 | 不低于 60% |
| 单次记录耗时 | 从进入应用到保存成功的中位耗时 | 不超过 20 秒 |

### 3.3 非目标（本期明确不做）

- 多人协作与团队看板
- 强社交功能，如排行榜、好友 PK
- 依赖服务端常驻的实时推送（当前采用本地提醒，订阅消息为可选增强）
- 跨端自动同步（当前采用本地存储加手动备份搬运）

## 4. 用户与场景

### 4.1 目标用户

注重自我管理的个人用户，以手机为主要使用端，偏好轻量、可爱、无学习成本的界面；对数据隐私敏感，不希望个人数据被强制上传云端。

### 4.2 典型场景

| 场景 | 用户行为 | 产品支撑 |
| --- | --- | --- |
| 早上到公司 | 想快速知道今天要做什么，并打个卡 | 桌面页：问候卡、今日日程、打卡按钮 |
| 读了一会儿书 | 想记下本次读了多少页 | 阅读 → 书架 → 输入本次页数 → 自动累加 |
| 临时记一件事 | 想快速把想法塞进便签 | 顶栏「+ 快速添加」或模板库一键套用 |
| 周末回顾 | 想看这一周到底做了什么 | 周复盘 → 自动生成成长报告 → 一键写入「做得好」 |
| 想知道某天干了什么 | 查看历史某一天的全部记录 | 桌面日历点选那一天 → 当天全记录时间轴 |
| 换手机或担心丢数据 | 需要导出备份 | 我的 → 数据备份 → 导出或导入 JSON |

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | Web 单文件、无构建依赖，首屏秒开；小程序页面切换无白屏；列表渲染无卡顿 |
| 兼容性 | Web 支持现代 Chrome、Safari、Edge，支持 PWA 安装与离线访问；小程序覆盖微信主流版本，兼容 iOS 与 Android |
| 视觉 | 移动端优先；小程序统一使用 rpx 单位（WXML 与 WXSS 中禁用 px）；支持日间与夜间模式及自定义背景 |
| 数据 | 本地优先（Web 存储键 gubao_desk_v1，小程序使用 Storage）；加载时补齐缺失字段；离线可用 |
| 隐私 | 默认不上传任何数据；云端同步必须由用户主动登录触发 |
| 健壮性 | 渲染异常具备兜底展示；旧缓存可被识别（版本号加 Service Worker 版本号双重校验） |
| 可维护性 | 双端共享同一套领域逻辑命名（如 searchAll、dayLevel、tlNodes），便于同步演进 |

## 8. 交互与视觉规范

1. **导航**：移动端由左上角轻量卡片按钮唤起抽屉；抽屉打开时该按钮隐藏，点击抽屉外空白区域关闭。按钮样式与页面卡片体系保持一致，避免视觉突兀。
2. **列表项**：左侧为图标与标题，右侧为操作区（编辑、删除）；删除需二次确认。
3. **弹层**：小程序采用不透明全屏面板，避免出现「透过遮罩看到上一层」的错觉；Web 采用半透明模糊遮罩。弹层内按钮不得重复（如只读弹窗仅保留「关闭」）。
4. **表单**：小程序统一使用 form 提交；枚举型选择使用内联按钮组而非滚轮选择器；日期仍使用原生选择器。
5. **反馈**：保存后提示，达成后彩带，出错后给出明确文案，不允许静默失败。
6. **文案**：轻松可爱、口语化，例如「书架空空的，添加第一本书吧」。
7. **搜索**：结果覆盖标题、正文与附属字段（如便签正文、储蓄目标名、课程笔记），避免用户「明明有却搜不到」。

## 9. 数据模型（摘要）

双端共用单一 DB 结构；Web 存储键为 gubao_desk_v1，小程序使用同构结构。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| profile | object | 昵称、签名、头像、标签 |
| checkins | map | 日期到签到时间的映射 |
| plans | map | 日期到计划项数组的映射，计划项含 id、名称、完成状态、优先级 |
| courses / exam | array | 课程列表与备考科目列表 |
| studyLog / readLog | map | 日期到学习或阅读分钟的映射 |
| workout | map | 日期到运动记录数组的映射，记录含 id、类型、时长、消耗 |
| finance | array | 收支流水，含类型、金额、分类、备注、日期 |
| goals | array | 储蓄目标，含名称、目标金额、已存金额 |
| ideas / pubs | array | 自媒体灵感与发布登记 |
| books / quotes | array | 书架条目与摘抄 |
| skills / skillLog | array | 技能定义与练习记录 |
| memos | array | 便签，正文参与全局搜索 |
| reviews | map | 周起始日到复盘内容的映射，含做得好、待改进、下周计划、时间 |
| reminders | object | 计划与锻炼提醒（时间点）、喝水提醒（间隔） |

## 10. 技术架构与约束

整体分为三层：UI 层（小程序页面与 Web 单页）、逻辑层（领域函数与工具模块）、数据层（本地存储与可选云端同步）。双端在逻辑层保持同名函数，以降低同步演进成本。

```
UI 层      小程序页面(WXML/WXSS)   |   Web 单页(index.html)
逻辑层     统一领域函数：searchAll / tlNodes / dayLevel / report ...
数据层     本地存储(localStorage 或 Storage)  <->  云端同步(可选)
```

### 10.1 关键约束与已定方案

| 约束 | 方案 |
| --- | --- |
| 真机数据更新异步，且失焦与点击时序不确定 | 弹层全面采用 form 提交 |
| 点击输入框导致弹层消失（点击事件冒泡） | 遮罩关闭采用目标元素与当前元素一致性判定 |
| 半透明遮罩被感知为界面重叠 | 小程序弹层遮罩改为完全不透明 |
| 旧缓存让用户看到过期界面 | 版本号可见，并升级 Service Worker 版本号 |
| 小程序无法直接打开外部浏览器 | 「联网搜书」改为复制关键词到剪贴板 |
| 滚轮选择器在部分环境不可交互 | 改为内联可选按钮组（分类、优先级、状态、平台） |
