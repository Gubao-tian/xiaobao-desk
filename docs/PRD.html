1背景与目标

要解决的三件事

  • 记录入口分散 —— 想记一件事先要纠结"打开哪个 App"，成本高到干脆不记。
  • 缺少反馈闭环 —— 记完没有可视化回馈，难以形成习惯。
  • 回顾成本高 —— 想知道"上周做了什么"要翻好几个地方，几乎不可能坚持复盘。

产品目标

G1 一个入口完成 15 类记录单模块完成一次记录 ≤ 3 次点击
G2 降低记录成本模板库、快速添加、表单默认值、快捷按钮
G3 建立正反馈闭环连续天数、热力图、成长报告、战绩卡
G4 让回顾变简单时间轴、全局搜索、周复盘自动汇总
G5 数据自主可控本地优先存储，一键导出 / 恢复
非目标不做多人协作、强社交、实时服务端推送

2用户与场景

目标用户：注重自我管理的个人用户，手机为主，偏好轻量、可爱、零学习成本；对数据隐私敏感。

场景用户行为产品支撑
早上到工位看今天要做什么、打个卡桌面：问候卡 + 今日日程 + 打卡
读了一会儿书记本次读了多少页阅读 → 输入本次页数 → 累加
临时记一件事快速塞进便签顶栏「+ 快速添加」/ 模板库
周末回顾看这周做了什么周复盘 → 自动成长报告 → 写进"做得好"
想查某天看历史记录桌面日历点那天 → 当天全部记录
换手机 / 怕丢导出备份我的 → 数据备份 → 导出 / 导入 JSON

5非功能需求

类别要求
性能Web 单文件无构建依赖、首屏秒开；小程序切换无白屏；列表渲染不卡
兼容现代 Chrome / Safari / Edge，支持 PWA 安装与离线；微信主流版本 iOS + Android
视觉移动端优先；小程序使用 rpx（禁用 px）；支持日/夜模式与自定义背景
数据本地优先（gubao_desk_v1 / Storage）；加载补齐缺失字段；离线可用
隐私默认不上传；云端同步需用户主动触发
健壮性渲染异常有兜底；旧缓存可识别（版本号 + Service Worker 版本号）
可维护性双端共享领域逻辑命名（searchAll / dayLevel / tlNodes）

6交互与视觉规范

  • 导航：移动端从左上角轻量卡片按钮唤起抽屉；抽屉打开时按钮隐藏，点抽屉外空白关闭。
  • 列表项：左侧图标 / 标题 + 右侧操作（✎ 编辑、🗑 删除）；删除二次确认。
  • 弹层：小程序不透明全屏 sheet（避免"透过遮罩看到上一层"）；Web 半透明模糊；只读弹窗只留「关闭」。
  • 表单：小程序统一 <form bindsubmit>；枚举用内联按钮组；日期用原生 picker。
  • 反馈：保存 → toast；达成 → 彩带；错误 → 明确文案，禁止静默失败。
  • 文案：轻松可爱、口语化（例："书架空空的，添加第一本书吧"）。

7技术架构与约束

┌─────────────── UI 层 ───────────────┐ │ 小程序页面(WXML/WXSS) │ Web 单页(index.html) │ ├─────────────── 逻辑层 ──────────────┤ │ utils/store · search · report · remind · theme · nav │ │ index.html 内同名函数（searchAll / tlNodes / dayLevel …） │ ├─────────────── 数据层 ──────────────┤ │ 本地存储（localStorage / Storage） ←→ 云端同步（可选） │ └─────────────────────────────────────┘
约束已定方案
真机 setData 异步 + blur/tap 时序不确定弹层全面采用 <form bindsubmit>
点输入框弹层消失（tap 冒泡）遮罩用 e.target === e.currentTarget 判断
半透明遮罩被感知为"界面重叠"小程序遮罩改为完全不透明
旧缓存让用户看到过期界面版本号可见 + Service Worker 版本升级
小程序无法打开外部浏览器「联网搜书」改为复制关键词到剪贴板
枚举 picker 在部分环境不可交互改为内联可选按钮组（分类 / 优先级 / 状态 / 平台）
